# Стратегии: как устроены и как добавить свою

Документ описывает четыре работающие стратегии по коду, а не по замыслу,
и показывает, как написать пятую. Всё, что здесь названо проверенным,
измерено на истории MEXC с контролем случайным входом — про метод замера
сказано в конце.

---

## 1. Общий договор

Стратегия — это один файл в `bot/strategies/`. Реестр (`strategies/index.js`)
читает папку сам: новый файл подхватывается при следующем запуске,
регистрировать его нигде не нужно. Файл обязан отдать объект по умолчанию
с полями `id` и `evaluate`, иначе будет пропущен с записью в лог.

```js
export default {
  id: "Моя-Стратегия",     // обязателен, попадает в карточку сигнала
  title: "Понятное имя",   // для людей
  timeframe: "1h",         // 1m 5m 15m 30m 1h 4h 1d
  warmup: 260,             // сколько баров нужно на прогрев индикаторов
  needsFutures: false,     // true — если нужны данные фьючерсов

  prepare(candles, symbol) { ... },        // индикаторы, один раз на пару
  conditions(candles, x, i) { ... },       // разложенные условия
  evaluate(candles, x, i) { ... },         // сигнал или null
  invalidated(candles, x, i, position) { ... },  // посылка сломалась?
};
```

### Что вызывается и когда

| Метод | Когда | Зачем |
|---|---|---|
| `prepare` | раз на пару за скан | Посчитать индикаторы по всей серии. Тяжёлое место — держать его лёгким. |
| `conditions` | на последнем закрытом баре | Разложить вход на список условий. Используется и для решения, и для показа «согласия стратегий» в карточке. |
| `evaluate` | там же | Вернуть сигнал, если **все** условия стороны выполнены. Иначе `null`. |
| `invalidated` | на каждом такте присмотра | Проверить открытую сделку: не сломалась ли посылка, по которой входили. |

Важно: движок смотрит **последний закрытый бар** (`i = candles.length - 2`),
а не формирующийся. Иначе сигнал появлялся бы и исчезал внутри часа.

### Формат сигнала

```js
return {
  side: "long",                 // long | short
  entry: 1.234,                 // цена входа
  sl: 1.200,                    // стоп
  targets: [t1, t2, t3, t4, t5],// ровно пять целей
  reason: "текст для карточки",
  detail: { что угодно },       // попадает в журнал
};
```

Лесенка выходов одна на всех: по 20% позиции на каждой цели, после первой
стоп уезжает в безубыток. Это заложено в мониторе и в бэктесте — если
стратегия отдаёт цели, они играются именно так.

### Формат условий

```js
conditions(c, x, i) {
  if (нет_данных) return null;       // прогрев не набран
  return {
    long:  [{ n: "название", ok: true|false }, ...],
    short: [{ n: "название", ok: true|false }, ...],
  };
}
```

Названия видны в чате, поэтому пишутся для человека: `CCI > 100`,
`цена над EMA200`. Если сторона не поддержана, отдайте один пункт
с `ok: false` и честным названием — так в карточке будет видно,
что стратегия туда не ходит.

## 2. Golden-Reverse

**Идея.** Геометрия выходов восстановлена из базы стороннего приложения:
415 сигналов, отношение «расстояние до первой цели» к «расстоянию до стопа»
равно ровно 0,500 в 23 случаях из 23. Их стоп примерно 1,5 ATR часа.
Правило входа разгадать не удалось, поэтому вход свой.

**Вход — все пять условий сразу:**

```
ЛОНГ
  1. флип UT Bot вверх          — трейлинг-стоп по ATR перевернулся
  2. CCI(20) > 100              — убеждённость, слабые флипы отсеиваются
  3. моментум растёт и > 0      — Squeeze Momentum по LazyBear
  4. цена выше EMA200           — фильтр направления
  5. сжатие в последние 6 баров — движение выходит из сжатия, а не из пустоты

ШОРТ — зеркально.
```

**Стоп.** За структурным экстремумом плюс четверть ATR, но зажатый
в диапазон от 1,0 до 2,5 ATR. Чистый ATR не объяснял наблюдавшиеся стопы,
чистая структура — тоже; зажатая структура воспроизводит разброс.
Если стоп ближе 0,15% от цены — сигнал отбрасывается: там шум и комиссия.

**Цели.** `entry ± 0,5·n·(расстояние до стопа)`, n от 1 до 5.

**Выход раньше стопа — три проверки:**

1. **Встречный сигнал** — UT Bot развернулся против позиции.
2. **Слом структуры** — цена ушла за свинговый уровень.
3. **Разворот моментума** — два бара подряд моментум против позиции.

Таймаута сознательно нет: позиция висит, пока жива посылка.

**Что можно подгонять под монету:** `cciMin` (60/100/140),
`utKey` (0,7/1/1,5), `sqzWindow` (3/6/12).

**Замер:** +0,005R на сделку при 67% в плюс; случайный вход −0,059R,
то есть отбор даёт +0,064R. На отдельной монете подгонка меняет картину
сильно: по ZEC умолчания давали 24% удачных и −0,01R, а `cciMin=60`
на проверочной части — +5,5R против +0,2R.

## 3. MA-Cross-CCI

**Идея, ради которой стратегия существует.** Вход делается **не после**
пересечения средних, а **до** него. Средние сходятся, скорость сближения
известна — значит момент встречи можно посчитать:

```
разрыв_сейчас = MA30[i] − MA60[i]
разрыв_три_бара_назад = MA30[i−3] − MA60[i−3]
скорость = (разрыв_сейчас − разрыв_три_бара_назад) / 3
баров_до_встречи = −разрыв_сейчас / скорость
```

Входим, когда до встречи остаётся не больше двух баров. Скорость берётся
за три бара, чтобы не ловить дрожь одного.

**Зачем так.** К моменту самого креста цена уже ушла, и вход после него
берёт хвост движения. Проверено: до последней цели доходят 18% сделок
против 10% при входе после креста.

**Вход:**

```
ЛОНГ
  1. MA30 идёт к MA60 снизу вверх и встретится в ближайшие 2 часа
  2. цена уже выше обеих средних
  3. CCI(14) ниже нуля
  4. CCI разворачивается вверх
```

Второе условие обязательно: без него матожидание падает вчетверо
(+0,049 против +0,202). Именно оно отделяет подтверждённое движение
от простого схождения линий.

Порог CCI буквально нулевой — «за серединой». Ужесточение до ±20 и ±40
только режет выборку, не улучшая результат.

**Что можно подгонять:** `leadBars` (1,5/2/3/4), `cciEdge` (0/20/40).
По `leadBars` устойчивая полка от 1,5 до 4 баров, всюду +0,17…+0,25R —
взята середина, а не лучшая точка, чтобы не подогнать под шум.

## 4. SMC-Confluence

**Идея.** Тот же спусковой крючок, что у Golden-Reverse, плюс согласие
структуры рынка по методу Smart Money Concepts: смещение должно совпадать
и на внутренних ногах (5 баров), и на свинговых (50). Покупаем только
когда мелкая и крупная структура смотрят в одну сторону.

**Вход — семь условий:** пять от Golden-Reverse плюс
`внутренняя структура вверх` и `свинговая структура вверх`.

**Что дал фильтр** (25 пар, 125 дней часовой истории):

| набор | сделок | в плюс | на сделку |
|---|---|---|---|
| без структуры (это Golden-Reverse) | 414 | 71% | +0,191R |
| + внутренняя структура | 343 | 73% | +0,240R |
| + свинговая структура | 284 | 73% | +0,227R |
| **+ обе** | **239** | **74%** | **+0,248R** |

Фильтр отсекает 42% входов и поднимает матожидание на треть.

**Что из SMC проверено и не вошло:** зона дискаунт/премиум дала +0,282R,
но на 88 сделках — выборка втрое меньше, доверия нет. Касание ордер-блока —
всего 4 сделки за 125 дней, ловить нечего.

Стратегия оставлена отдельной, а не влита в Golden-Reverse, чтобы `/stats`
сравнивал их на живых сделках, а не только на истории.

**Что можно подгонять:** `cciMin` (60/100/140), `legsSwing` (30/50/80),
`sqzWindow` (3/6/12).

## 5. Funding-Impulse

Единственная стратегия, которая смотрит не на цену.

**Идея.** Ставка финансирования по бессрочным фьючерсам говорит, за какую
сторону рынок доплачивает прямо сейчас. Расхожее мнение — что высокая
ставка означает перекос и скорый вынос толпы. **Проверка это опровергла:**
на 59 ликвидных парах за семь месяцев после ставки выше 0,03% средний ход
за двое суток оказался выше, а не ниже случайного. Здесь ставка —
признак живого импульса.

Сырые числа, по полосам ставки, ход цены за 48 часов:

| ставка | случаев | средний ход | вверх |
|---|---|---|---|
| ≤ −0,5% | 38 | −7,3% | 32% |
| −0,1…0% | 12641 | +0,7% | 49% |
| 0…0,02% | 26418 | +0,5% | 46% |
| 0,02…0,1% | 1453 | +2,5% | 51% |
| > 0,1% | 71 | +15,2% | 62% |

**Два этапа.** Ставка пересчитывается раз в восемь часов и спусковым
крючком быть не может. Отсюда разделение:

```
ЭТАП 1 — наблюдение (метод watching)
  ставка > 0,03% и цена не под EMA50
  → «👀 Взял на прицел», одно сообщение на монету в сутки

ЭТАП 2 — вход (метод evaluate)
  ставка > 0,03%
  цена выше EMA50
  цена обновила максимум за последние 12 часов
  → полноценная карточка сигнала
```

Без второго этапа превосходство падает с +0,236R до +0,058R: ставка даёт
направление, но не момент входа.

**Стоп** — 1,5 ATR. **Цели** — доли среднедневного хода монеты, а не доли
стопа: `entry + 0,2·дневной_ход·n`. Так пять целей укладываются в двое
суток по построению. У монеты с ходом 5% в день пятая цель — один дневной
ход, а не абстрактные 2,5R, до которых половина монет ползёт неделю.

**Жизнь сигнала — 48 часов.** Дальше `invalidated` закрывает его сам:
импульс, не отработавший за двое суток, уже угас. Плюс выход, если цена
ушла под EMA50 или ставка ушла в минус.

**Замер:** +0,197R на сделку, 63% в плюс, 128 сигналов. Случайный вход
−0,039R, превосходство +0,236R. Держится на всех третях периода
(+0,04 · +0,01 · +0,51) — единственная из проверенных схем, у которой так.

**Чего не умеет:** шорт не проверялся; без бессрочного контракта на паре
молчит; в спокойные месяцы теряет — разброс по месяцам от −0,29R до +0,48R,
и это её природа, а не изъян.

## 5а. Сканер отстающих (не стратегия)

Живёт в `bot/scanners.js`, а не в папке стратегий, потому что ищет
не сигнал в одной монете, а **пару**: обычная стратегия видит только
свою пару и такое увидеть не может.

> ⚠️ **Замер ниже устарел.** 25 августа в сравнении форм нашлась ошибка
> направления сдвига (см. ниже). Цифра +0,353R получена на коде с этой
> ошибкой и к нынешнему коду не относится. До нового замера сканер
> лучше держать выключенным: `/settings` → «Сканер отстающих».

**Идея.** Монета-лидер сделала резкий скачок. Среди остальных ищем ту,
чей **сегодняшний** график повторяет график лидера, каким он был
несколько часов назад, и которая сама ещё почти не двинулась. Ставка в
том, что она повторит движение с тем же лагом.

**Как считается похожесть.** Берётся окно в 96 пятнадцатиминутных
свечей, приводится к первой свече в процентах — получается форма
кривой, независимая от абсолютной цены. Форма кандидата берётся до
последнего закрытого бара, форма лидера — с отступом назад на величину
сдвига; сравниваются корреляцией Пирсона, берётся лучший сдвиг.

**Направление сдвига.** Если кандидат отстаёт на N баров, то его
сегодняшняя форма похожа на форму лидера N баров назад. До 25 августа
отматывался назад кандидат, а не лидер, — сравнение шло ровно наоборот.
На проверке, где кандидат заведомо повторял лидера с задержкой в 12
баров, находился сдвиг 1 при совпадении 5%; после разворота — 12 при
100%. Значит связки, которые сканер выдавал раньше, держались на
случайном сходстве, а не на запаздывании.

**Отступ не меньше двух часов.** Скачок лидера меряется за 8 баров.
При меньшем сдвиге окно лидера попадало бы внутрь самого скачка, и
тихая форма кандидата сравнивалась бы с уже разогнавшимся лидером.

**Условия связки:**

```
1. лидер прошёл ≥8% за 2 часа (8 баров)
2. кандидат прошёл меньше 35% от этого движения — то есть ещё стоит
3. сегодняшняя форма кандидата совпадает на ≥85% с формой лидера,
   отмотанной назад на 2–4 часа (перебираются все такие отступы)
```

**Геометрия.** Стоп 1,25 ATR пятнадцатиминутки, шаг цели 1,5 ATR.
Направление то же, что у лидера: скакнул вверх — берём лонг.

**Таймфрейм принципиален.** Замер на сорока ликвидных парах за два
месяца:

| данные | превосходство над случайной монетой |
|---|---|
| часовые свечи, 14 разных настроек | ни в одной |
| пятнадцатиминутные | **+0,353R** |

На часах лаг в один-четыре бара слишком груб для сдвига, который
меряется минутами. Поэтому сканер работает только на 15-минутках.

**Почему именно эта геометрия.** Перебор дал плато, а не пик: во всём
прямоугольнике стопа от 1 до 1,5 ATR и цели от 0,75 до 2 ATR
превосходство положительно и все трети периода неотрицательны. Лучшая
клетка давала +0,479R, но взята середина области — брать пик значит
подгонять под шум.

**Настройки** — отдельный раздел «Сканер отстающих» в `/settings`,
меняются прямо в Telegram и применяются со следующего скана:

| Настройка | По умолчанию | Что делает |
|---|---|---|
| Сканер | включён | выключатель целиком |
| Скачок лидера от | 8% | что считать резким движением |
| Совпадение графиков | 85% | насколько похожи формы |
| Сдвиг не больше | 4 ч | предел лага между графиками |
| Ведомая прошла до | 35% от скачка | насколько она ещё «стои́т» |

Пороги вынесены не для красоты: рынок меняется, и в спокойные недели
скачков в восемь процентов почти не бывает — порог приходится опускать,
чтобы сканер вообще что-то видел. На живой проверке порог 8% давал
тишину, 2% — одну связку, а смягчение совпадения с 85% до 70%
поднимало число связок с одной до трёх.

## 6. Как добавить свою стратегию

### Шаг 1. Создать файл

`bot/strategies/моя-стратегия.js`. Имя файла любое, кроме `index.js`.

### Шаг 2. Написать заготовку

```js
import { atr, ema, cci } from "../indicators.js";

const DEFAULTS = {
  emaLen: 50,
  cciMin: 100,
  stopAtr: 1.5,
  minStopPct: 0.15,
};

/** Что перебирать при подгонке под монету. Можно не объявлять. */
export const TUNABLE = {
  cciMin:  [80, 100, 120],
  stopAtr: [1, 1.5, 2],
};

export function make(over = {}) {
  const P = { ...DEFAULTS, ...over };
  return {
  id: "Моя-Стратегия",
  title: "Что она делает",
  timeframe: "1h",
  warmup: 120,

  prepare(c) {
    return {
      atr: atr(c, 14),
      ema: ema(c.map(y => y.c), P.emaLen),
      cci: cci(c, 20),
    };
  },

  conditions(c, x, i) {
    if (x.atr[i] == null || x.ema[i] == null || x.cci[i] == null) return null;
    return {
      long: [
        { n: `CCI > ${P.cciMin}`, ok: x.cci[i] > P.cciMin },
        { n: "цена над EMA",      ok: c[i].c > x.ema[i] },
      ],
      short: [
        { n: `CCI < −${P.cciMin}`, ok: x.cci[i] < -P.cciMin },
        { n: "цена под EMA",       ok: c[i].c < x.ema[i] },
      ],
    };
  },

  evaluate(c, x, i) {
    const cond = this.conditions(c, x, i);
    if (!cond) return null;
    const long = cond.long.every(z => z.ok);
    const short = cond.short.every(z => z.ok);
    if (!long && !short) return null;

    const side = long ? "long" : "short";
    const entry = c[i].c;
    const dist = P.stopAtr * x.atr[i];
    if (dist / entry * 100 < P.minStopPct) return null;   // шум

    const sl = long ? entry - dist : entry + dist;
    return {
      side, entry, sl,
      targets: [1, 2, 3, 4, 5].map(n =>
        long ? entry + 0.5 * n * dist : entry - 0.5 * n * dist),
      reason: `CCI ${x.cci[i].toFixed(0)} · цена ${long ? "над" : "под"} EMA`,
    };
  },

  /** Не обязателен. Без него сделка живёт до стопа или целей. */
  invalidated(c, x, i, pos) {
    const long = pos.side === "long";
    const e = x.ema[i];
    if (e != null && (long ? c[i].c < e : c[i].c > e))
      return { reason: "тренд", label: "Цена ушла за EMA",
               detail: "посылка, по которой входили, больше не верна" };
    return null;
  },
};
}

export default make();
```

### Шаг 3. Обязательные мелочи, на которых легко споткнуться

- **`export default make()` в конце.** Реестр берёт объект по умолчанию.
  Без этой строки файл будет пропущен.
- **Фабрика `make`.** Нужна подгонщику параметров. Без неё стратегия
  работает, но `/tune` её не тронет.
- **Проверка `warmup`.** Если индикаторам нужно 200 баров, поставьте
  `warmup: 220`. Движок тянет 300 свечей — на большее рассчитывать нельзя.
- **`conditions` возвращает `null`**, пока данных не хватает. Не бросайте
  исключение: одна упавшая стратегия не должна ронять скан.
- **Ровно пять целей.** Монитор и отчёты рассчитаны на лесенку из пяти.

### Шаг 4. Временно выключить

```js
enabled: false,     // рядом с id
```

Реестр напишет в лог «выключена в файле стратегии» и пройдёт мимо.
Так лежит `zone-retest.js` — проверенная и отвергнутая стратегия,
которую жалко удалить, но незачем включать.

### Шаг 5. Проверить перед запуском

```
node --check bot/strategies/моя-стратегия.js
sh bot/termux-run.sh restart
```

В логе должно появиться имя стратегии в строке «стратегий загружено».
Если не появилось — там же будет причина.

## 7. Как проверять стратегию на истории

Три правила, выведенные из собственных ошибок в этом проекте.

**Правило первое: всегда контроль случайным входом.** Возьмите те же
сигналы, но подставьте случайный бар с той же геометрией стопа и целей.
Лесенка с безубытком сама по себе прибыльна на растущем отрезке рынка,
и без контроля любая схема выглядит работающей. Мерило — разница между
стратегией и случайностью, а не абсолютное число.

**Правило второе: выборку собирать по обороту в долларах.** Колонка
`volume` у бирж — объём **в монетах**. У монеты по 1e-11 их триллионы,
и сортировка по этой колонке выносит наверх мемкоины. В этом проекте так
и вышло: «56 ликвидных пар MEXC» оказались сплошь AIDOGE и BABYDOGE,
ни одной дороже цента, и результат по ним пришлось выбросить целиком.
Оборот в долларах = `volume × close`.

**Правило третье: проверять устойчивость двумя разрезами.** Разбейте
монеты на две непересекающиеся половины и посчитайте отдельно; то же
по третям периода. Настройка, работающая только на одной половине или
только на одном отрезке времени, — находка перебора, а не преимущество.
Именно так отвалился построитель зон: на мемкоинах он давал +0,036R
превосходства, на ликвидных парах — минус три тысячных, то есть ноль.

## 8. Справочник индикаторов

Всё в `bot/indicators.js`, сверено с TradingView (ATR в пределах 0,3%,
CCI в пределах 1,6 пункта).

| Функция | Что даёт |
|---|---|
| `atr(c, n)` | Средний истинный диапазон по Уайлдеру |
| `ema(values, n)` / `sma(values, n)` | Скользящие |
| `cci(c, n)` | Индекс товарного канала |
| `squeeze(c)` | Squeeze Momentum по LazyBear: `.mom` и `.on` |
| `utBot(c, {keyValue, atrPeriod})` | Трейлинг по ATR: `.buy` и `.sell` |
| `structure(c, len)` | Свинговые уровни: `.lastHigh`, `.lastLow` |
| `dailyVolatility(daily, days)` | Средний дневной размах в процентах |

Структура рынка — в `bot/smc.js`:

| Функция | Что даёт |
|---|---|
| `structureBias(c, size)` | Смещение (`BULL`/`BEAR`), событие BOS или CHoCH |
| `zonePos(c, ...)` | Положение цены между дискаунтом и премиумом |
| `orderBlocks(c, ...)` | Блоки заявок |

Ставки финансирования — в `bot/data/funding.js`:

| Функция | Что даёт |
|---|---|
| `rateOf(symbol)` | Ставка в процентах или `null` |
| `infoOf(symbol)` | Ставка, открытый интерес, последняя цена |

Стратегии, которым нужны ставки, объявляют `needsFutures: true` —
тогда движок обновит их перед сканом.
