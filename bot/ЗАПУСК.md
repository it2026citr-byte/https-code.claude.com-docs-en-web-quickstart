# Бот-источник сигналов — запуск

Бот **@Alfbi_bot**. Мозг работает на твоём компьютере, телефон — пульт.
Пока компьютер выключен, бот молчит; при включении догоняет и докладывает,
сколько его не было.

> **Хочешь запустить прямо на телефоне?** Так тоже можно —
> см. `ЗАПУСК-НА-ТЕЛЕФОНЕ.md`. Просто распаковать архив мало:
> это не приложение, ему нужен Node.js.

## Что нужно

Только **Node.js версии 22.5 или новее**. Больше ничего:
ни `npm install`, ни базы данных, ни компиляторов. Всё встроено.

Проверить:

```
node -v
```

Если версия старше 22.5 или Node нет — поставить с nodejs.org (кнопка LTS).

## Запуск

**Windows.** Открыть папку `bot`, в адресной строке проводника набрать `cmd`,
Enter, затем:

```
npm start
```

**Mac / Linux.** В терминале:

```
cd путь/к/bot
npm start
```

Признак того, что всё хорошо:

```
[18:47:08] бот @Alfbi_bot на связи
[18:47:09] TradingView: 1674 пар, после фильтров 67
[18:47:09] опрос Telegram запущен
```

Дальше — в Telegram найти **@Alfbi_bot** и нажать «Начать».

Окно терминала закрывать нельзя: закроешь — бот остановится.
Сворачивать можно.

## Команды

| Команда | Что делает |
|---|---|
| `/status` | режим, когда последний раз видел рынок, открытые сделки |
| `/focus` | **бросить всё и следить только за взятыми сделками** — проверка каждые 10 секунд вместо 15 минут |
| `/scan` | вернуться к поиску новых точек входа |
| `/pulse` | включить/выключить сводку по рынку раз в 15 минут |
| `/results` | итоги закрытых сигналов за сегодня, карточками |
| `/log` | итоги месяца + выгрузка CSV и ленты событий файлами |
| `/stats` | статистика за всё время, по месяцам и по стратегиям |
| `/positions` | открытые сделки, текущий R, закрыть вручную |
| `/users` | кто имеет доступ; выдать или отозвать |
| `/help` | список команд |

Месяц можно указать: `/log 2026-07`.

Telegram принимает в командах только латиницу, но бот отзывается и на
русские: `/статус` `/фокус` `/скан` `/пульс` `/итоги` `/журнал` `/стата` `/помощь`.

## Доступ закрыт

Бота видно в поиске Telegram — спрятать его нельзя. Поэтому доступ по заявке:

* **Ты** работаешь сразу. Твой id прописан в `.env` как `OWNER_ID`.
* **Любой другой** получает «Этот бот приватный», а тебе прилетает заявка
  с кнопками **✅ Разрешить** / **🚫 Отказать** и его именем с id.
* Пока ты не нажал «Разрешить», человек не увидит ни одного сигнала.
* `/users` — список всех, кто стучался, с кнопкой отозвать доступ.

Если `OWNER_ID` в `.env` пуст, владельцем станет тот, кто первым напишет
`/start`. С заполненным — переназначить можно только правкой файла.

Дополнительно у BotFather стоит выключить `/setjoingroups`, чтобы бота
нельзя было добавить в чужую группу.

## Стратегия

Пока одна — **Golden-Reverse**. Геометрия выходов взята из разбора
приложения Crypto Signals Golden (415 сигналов): цели стоят на
0,5 · 1 · 1,5 · 2 · 2,5 расстояния до стопа. Стоп — за структурным
экстремумом, зажатый в диапазон 1,0–2,5 ATR(1ч), который наблюдался у них.

Вход требует **пяти условий сразу**:

1. флип скользящего стопа UT Bot;
2. CCI за ±100 — убеждённость, а не шорох;
3. моментум Squeeze растёт (для лонга) и положителен;
4. цена по нужную сторону EMA200 — торгуем по тренду;
5. в последних 6 барах было сжатие Боллинджера внутри Кельтнера.

Смягчение любого из пяти роняет матожидание вдвое и больше — проверено
прогоном по 60 парам за ~500 часов:

| Правило | Сигналов/сутки | Винрейт | Стопы | ср. R |
|---|---|---|---|---|
| без фильтров | 49 | 62% | 38% | −0,09 |
| + тренд | 33 | 65% | 35% | −0,06 |
| + CCI > 60 + сжатие | 12 | 75% | 24% | +0,15 |
| **+ CCI > 100 (текущее)** | **9** | **75%** | **23%** | **+0,23** |

**Честно о цифрах.** Это 60 сделок за три недели одного рынка, не
доказательство. Направление верное — жёсткие фильтры лучше мягких, —
но величину +0,23R всерьёз принимать рано. Настоящая проверка на этапе
бэктеста, по годам, а не по неделям.

Искусственного потолка на число сигналов **нет**: `maxSignalsPerScan: 0`.
Бот выдаёт ровно столько, сколько даёт стратегия.

## Что в карточке сигнала

```
📈 LONG ZROUSDT ⟨1г 8.4% · 3м 8.1% · 2н 7.6%⟩   Golden-Reverse · 1ч
Вход 1.1023 · Стоп 1.0083 (8.53%)
Цели 1.1493 · 1.1963 · 1.2433 · 1.2903 · 1.3373
UT Bot флип вверх · CCI 222 · моментум растёт · тренд вверх · после сжатия
```

В угловых скобках — **средний дневной ход монеты** в процентах: за год,
за три месяца и за две недели. Считается как среднее `(верх − низ) / закрытие`
по дневным свечам.

Зачем: сразу видно, нормален ли стоп для этой монеты. У ZRO стоп 8,5% при
среднесуточном ходе 7,6% — то есть чуть больше одного обычного дня.
У BTC средний ход 3%, и стоп в 8% там означал бы совсем другое.
Расхождение колонок показывает, разогналась монета или успокоилась:
2н выше 1г — волатильность растёт.

Тильда (`~8.1%`) значит, что монета моложе года и окно неполное.

Дневные свечи тянутся только по парам, где сигнал уже нашёлся,
и кешируются на 6 часов — по всем 68 парам их дёргать незачем.

## Присмотр за сделкой

Взятая сделка проверяется автоматически. Три вещи:

**Цели.** Лесенка 20% на каждой из пяти. После первой цели стоп
переводится в безубыток — так же, как считался бэктест.

```
🎯 Цель 2 · 77158.75
BTCUSDT LONG · зафиксировано +0.30R
Стоп переведён в безубыток 76158.75
Следующая цель 77658.75
```

**Стоп.** Закрывает сделку и подводит итог. Отдельно помечается стоп
в безубытке — это не потеря.

```
🔴 Стоп · 2536.75
ETHUSDT LONG · итог −1.00R
```

**Слом стратегии** — то, ради чего всё затевалось. Три проверки,
любая закрывает вопрос:

| Проверка | Когда срабатывает |
|---|---|
| Встречный сигнал | стратегия выдала разворот в другую сторону |
| Слом структуры (CHoCH) | закрытие за последним свинговым экстремумом |
| Разворот моментума | два бара подряд против позиции |

```
🟠 ВЫХОД — стратегия сломана
ETHUSDT SHORT

Встречный сигнал стратегии: UT Bot развернулся вверх

Цена 2436.75 · стоп 2736.75 · сейчас +0.70R
Посылка сделки умерла. Выходи, не дожидаясь стопа.

[ ✅ Вышел ]  [ ⏳ Остаюсь ]
```

Бот **не закрывает сделку сам** — он не торгует. «Вышел» запишет
результат по текущей цене, «Остаюсь» оставит позицию под присмотром
и не повторит эту же тревогу.

Таймаута нет: пока посылка жива, сделка висит сколько нужно.

Каждая тревога уходит один раз — ключ по паре (позиция, причина).
Перезапуск бота повторов не создаёт.

Цели и стоп проверяются по цене: раз в 15 минут обычно, раз в 10 секунд
в фокусе. Слом стратегии считается один раз на закрытии часового бара —
на индикаторы нужны свечи, гонять их каждые 10 секунд незачем.

`/positions` — открытые сделки с текущим результатом и кнопкой закрыть.

## Нитка по сделке

Взятый сигнал не теряется в ленте. Карточка правится на «✅ В работе»,
а всё, что случится дальше — взятие, каждая цель, перенос стопа в безубыток,
слом стратегии, закрытие — приходит **ответами на эту же карточку**.
В Telegram получается нитка: тапнул по ответу — прыгнул к исходному сигналу,
и вся история сделки читается сверху вниз в одном месте.

Технически id карточки хранится в `positions.msg_id`. Если сообщение удалить,
событие всё равно придёт — просто отдельным сообщением, а не ответом.

## Журнал и отчёты

Бот пишет всё, что делает, в две вещи сразу:

* **таблица сделок** — `storage/journal/ГГГГ-ММ.csv`. Первые семь колонок
  один в один как в `golden-signals-all.csv`, дальше добавлены стратегия,
  время открытия, результат в R и таймфрейм. Обе базы читаются одним скриптом;
* **лента событий** — `storage/journal/ГГГГ-ММ.log.txt`, построчно всё:
  выдача сигнала, взятие в работу, каждая цель, стоп, слом стратегии.

Отчёты приходят сами:

| Когда | Что |
|---|---|
| Каждый день в 20:00 UTC | карточки закрытых за день + строка итога. Если закрывать было нечего — бот молчит |
| Первого числа | итог месяца по статусам и стратегиям, плюс оба файла вложением |

Час дневной сводки — `reportHourUtc` в `config.js`.

Если компьютер был выключен в момент отчёта, тот уйдёт при следующем запуске:
срок проверяется раз в минуту по журналу, а не по таймеру в памяти.

## Настройки

`config.js`, менять можно на ходу (после правки перезапустить):

| Параметр | Сейчас | Смысл |
|---|---|---|
| `scanIntervalMin` | 15 | как часто искать новые монеты |
| `focusIntervalSec` | 10 | как часто проверять сделки в фокусе |
| `normalWatchMin` | 15 | как часто проверять сделки вне фокуса |
| `minTurnoverUsd` | 1 000 000 | ниже этого оборота пары отбрасываются |
| `topByTurnover` | 80 | сколько пар держать в работе |
| `riskPct` | 1 | риск на сделку, % депозита |
| `maxSignalsPerScan` | 0 | 0 — без ограничения; аварийный тормоз, не отбор |
| `bulkPriceThreshold` | 21 | до скольких пар цены брать поштучно |

## Сколько это ест трафика

Измерено на проводе, с заголовками и сжатием:

| Что | Вес |
|---|---|
| Цена одной пары | 829 б (из них 790 — заголовки, данных 39 б) |
| Весь список цен MEXC | 17 497 б в gzip |
| Свечи одной пары | 10 427 б |
| Один полный скан 68 пар | 0,76 МБ |

| Режим | За сутки |
|---|---|
| Скан, раз в 15 минут | **73 МБ** |
| Фокус с 1 сделкой, раз в 10 с | **7 МБ** |
| Фокус с 3 сделками | **21 МБ** |
| Фокус с 10 сделками | **72 МБ** |

Порог `bulkPriceThreshold: 21` взят не на глаз: 17 497 / 829 = 21,1 —
ровно там один общий запрос становится дешевле поштучных.

На домашнем Wi-Fi это неважно. На мобильном тарифе фокус с тремя
сделками — около 650 МБ в месяц; считай.

Дальнейшее удешевление — не в подборе порога, а в переходе на поток
MEXC по WebSocket: заголовки там платятся один раз за соединение,
а не 8640 раз в сутки.
| `reportHourUtc` | 20 | час UTC для дневной сводки |

При пороге 1 млн $ в работе оказывается около 67 пар из 1674 на MEXC.
Понизишь порог — пар станет больше, но на фьючерсах в неликвиде
проскальзывание съедает выигрыш.

## Автозапуск и сторож

Чтобы не поднимать бота руками после каждой перезагрузки — см.
**`АВТОЗАПУСК.md`**. Там сторож `termux-run.sh`: не даёт запуститься
второй копии, держит замок пробуждения, поднимает бота после падений
и ведёт лог с обрезкой.

```
sh ~/repo/bot/termux-run.sh          запустить
sh ~/repo/bot/termux-run.sh status   работает ли
sh ~/repo/bot/termux-run.sh stop     остановить
```

## Если что-то не так

**«не является внутренней или внешней командой» (npm)** — Node не установлен
или не прописан в PATH. Переустановить с nodejs.org и перезагрузиться.

**`BOT_COMMAND_INVALID`** — версия старая, обнови файлы.

**«запущен ещё один экземпляр бота»** — где-то остался открытый терминал
с ботом. Telegram не даёт двум процессам читать одну очередь.
Закрыть лишний.

**Бот не отвечает, в логе тишина** — проверь, доходит ли до Telegram:
открой в браузере `https://api.telegram.org/bot<ТОКЕН>/getMe`,
должно прийти `"ok":true`.

**Что-то с TradingView или MEXC** — в логе будет строка с HTTP-кодом.
Проверить вручную:

```
curl -s -o /dev/null -w "%{http_code}\n" "https://api.mexc.com/api/v3/ping"
```
