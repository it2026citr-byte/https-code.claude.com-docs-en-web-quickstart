# Анализ ТЗ и принятые решения

## Постановка

Внешний отчёт на СКД для 1С:ERP 2.5 (база `erp_copy2`): план/факт производства
в виде диаграмм Ганта по заказам на производство.

- **План** — начало из заказа на производство, длительность — общее «количество дней»
  из дополнительного реквизита документа-основания (заказ клиента / заказ давальца).
- **Факт** — по этапам производства внутри заказа на производство,
  доступен только после формирования этапов (статус «К производству»).
- **Вывод** — две диаграммы Ганта: отдельно по статусу «Формируется»,
  отдельно по статусу «К производству».

## Решения по спорным местам ТЗ (согласовано)

| Вопрос | Решение |
|---|---|
| Версия конфигурации | ERP 2.5.x (`ЗаказНаПроизводство2_5`, `ЭтапПроизводства2_5`, `СтатусыЗаказовНаПроизводство2_5`) |
| Плановый интервал | начало = дата начала ЗНП; окончание = начало + «Количество дней» из доп. реквизита основания |
| Факт по этапам | берём фактическую дату этапа, если она заполнена, иначе плановую дату этапа; интервал заказа = min(начало) … max(окончание) по всем его этапам |
| Формат сдачи | исходники + сборка `.erf` одной командой платформы (см. `docs/02-Сборка-и-настройка.md`) |

## Реализованная логика

Один запрос отдаёт **по две строки на заказ**:

- `ВидИнтервала = "План"` — для всех заказов в отборе;
- `ВидИнтервала = "Факт"` — только для заказов, по которым есть этапы производства.

Это даёт диаграмме Ганта готовые серии: точка — заказ, серия — План/Факт,
значение — пара ресурсов `ДатаНачала` / `ДатаОкончания`.

Правила расчёта планового окончания (в порядке приоритета):

1. `КоличествоДней > 0` → `ДатаНачалаЗаказа + КоличествоДней дней`;
2. иначе, если у ЗНП заполнена дата завершения → она;
3. иначе `ДатаНачалаЗаказа + 1 день` (чтобы полоса была видна на диаграмме).

«Количество дней» ищется сразу в трёх местах, какой бы способ хранения ни был настроен:
`Документ.ЗаказКлиента.ДополнительныеРеквизиты`,
`Документ.ЗаказДавальца.ДополнительныеРеквизиты`,
`РегистрСведений.ДополнительныеСведения`. Если у ЗНП несколько оснований —
берётся максимум (это и есть «общее количество дней по заказу»).

Сам доп. реквизит выбирается параметром `СвойствоКоличествоДней`; если пользователь
его не выбрал, модуль объекта подставляет первый реквизит с наименованием,
начинающимся на «Количество дней».

## Допущения по метаданным — ТРЕБУЮТ ПРОВЕРКИ

Конфигурации `erp_copy2` у меня не было (сборка велась вне вашего контура),
поэтому имена ниже взяты по типовой ERP 2.5. В запросе они помечены `[ПРОВЕРИТЬ]`.
Запустите `tools/ДиагностикаМетаданных.bsl` — он выведет фактические имена.

| Что | Предположение в коде | Где править |
|---|---|---|
| Дата начала ЗНП | `ЗаказНаПроизводство2_5.ДатаНачала` | шаг 1 запроса |
| Дата завершения ЗНП | `ЗаказНаПроизводство2_5.ДатаЗавершения` | шаг 1 запроса |
| Связь ЗНП → основание | ТЧ `Продукция.Заказ` | шаг 1 запроса |
| Связь этапа с ЗНП | `ЭтапПроизводства2_5.ЗаказНаПроизводство` | шаг 4 запроса |
| План этапа | `ЭтапПроизводства2_5.ДатаНачала` / `ДатаЗавершения` | шаг 4 запроса |
| Факт этапа | `ЭтапПроизводства2_5.ДатаНачалаФакт` / `ДатаЗавершенияФакт` | шаг 4 запроса |
| Статусы | `Перечисление.СтатусыЗаказовНаПроизводство2_5`: `Формируется`, `КПроизводству` | отборы диаграмм в схеме СКД |

Если фактические имена отличаются — это правки в одном-двух местах запроса,
структура отчёта не меняется.

## Открытые вопросы (не блокируют, но влияют на цифры)

1. **ЗНП без документа-основания или без заполненного «Количество дней».**
   Сейчас: план строится по датам самого ЗНП. Альтернатива — не показывать такие
   заказы вовсе либо подсвечивать их отдельной серией.
2. **Несколько оснований у одного ЗНП.** Сейчас берётся максимум дней.
   Возможные альтернативы: минимум, сумма, строка по каждому основанию.
3. **Масштаб оси.** Сейчас интервалы датированы по дням (доп. реквизит — дни).
   Если нужен посменный/почасовой разрез — меняется только отображение диаграммы.
4. **Отборы.** В отчёте есть период по дате начала ЗНП и список статусов.
   Нужны ли обязательные отборы по подразделению, менеджеру, номенклатуре?
5. **Закрытые заказы.** Сейчас в отбор не попадают (только «Формируется» и
   «К производству»), пометка удаления отсекается.
