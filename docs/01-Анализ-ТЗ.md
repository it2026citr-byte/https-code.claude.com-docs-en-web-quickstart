# Анализ ТЗ и принятые решения

## Постановка

Внешний отчёт на СКД для 1С:ERP 2.5 (база `erp_copy2`): план/факт производства
диаграммами Ганта по заказам на производство. Образец вывода — `ПРИМЕР.xlsx`
(две таблицы: «ПРОГНОЗ» и «ПЛАН»).

## Что взято из образца

| | Таблица «ПРОГНОЗ» | Таблица «ПЛАН» |
|---|---|---|
| Статус заказа на производство | «Формируется» | «К производству» |
| Иерархия строк | документ-основание → заказ на производство | документ-основание → заказ на производство → **этап производства** |
| Плановая полоса (в образце жёлтая) | «Начать не ранее» + «Срок изготовления, к дней» | то же, на уровне заказа |
| Фактическая полоса (в образце красная) | нет (этапы ещё не сформированы) | **на каждый этап отдельно**: «Начат» … «Завершен» |
| Колонки | Документ-основание, Заказ на производство, Начать не ранее, Начат, Завершен, Желаемая дата выпуска, Срок изготовления к дней | те же |

Масштаб оси в образце — один день на колонку, дни календарные
(в примере: ЗНП с «Начать не ранее» 10.06 и сроком 15 дней даёт полосу 10.06–25.06,
что совпадает с «Желаемой датой выпуска» 25.06).

## Решения по спорным местам ТЗ (согласовано)

| Вопрос | Решение |
|---|---|
| Версия конфигурации | ERP 2.5.x (`ЗаказНаПроизводство2_5`, `ЭтапПроизводства2_5`, `СтатусыЗаказовНаПроизводство2_5`) |
| Плановый интервал | начало = «Начать не ранее» заказа на производство; окончание = начало + «Срок изготовления, к дней» из доп. реквизита основания |
| Факт | по каждому этапу заказа отдельной полосой: фактические даты этапа, а если факт не проставлен — плановые даты этапа |
| Вывод | один вариант отчёта: диаграмма + расшифровка по «Формируется», затем то же по «К производству» |

## Реализованная логика

Запрос отдаёт строки двух видов:

- `ВидИнтервала = "План"` — по одной на пару «заказ на производство × документ-основание»,
  поля `ДатаНачала` = «Начать не ранее», `ДатаОкончания` = начало + срок;
- `ВидИнтервала = "Факт"` — по одной на **каждый этап** заказа,
  `ДатаНачала`/`ДатаОкончания` = фактические даты этапа, при их отсутствии — плановые.

Приоритет расчёта планового окончания:

1. `Срок изготовления > 0` → «Начать не ранее» + срок (календарных дней);
2. иначе, если «Желаемая дата выпуска» позже начала → она;
3. иначе начало + 1 день (чтобы полоса была видна).

«Срок изготовления, к дней» ищется в трёх местах — `ЗаказКлиента.ДополнительныеРеквизиты`,
`ЗаказДавальца.ДополнительныеРеквизиты`, `РегистрСведений.ДополнительныеСведения` —
и выбирается параметром `СвойствоСрокИзготовления`. Если параметр не заполнен,
модуль объекта подставляет первый доп. реквизит с наименованием «Срок изготовл…».

## Допущения по метаданным — ТРЕБУЮТ ПРОВЕРКИ

Конфигурации `erp_copy2` при сборке не было, имена ниже взяты по типовой ERP 2.5
и помечены в запросе как `[ПРОВЕРИТЬ]`. Запустите `tools/ДиагностикаМетаданных.bsl` —
он выведет фактические имена реквизитов.

| Что | Предположение в коде | Где править |
|---|---|---|
| «Начать не ранее» | `ЗаказНаПроизводство2_5.НачатьНеРанее` | шаг 1 запроса |
| «Желаемая дата выпуска» | `ЗаказНаПроизводство2_5.ЖелаемаяДатаВыпуска` | шаг 1 запроса |
| Связь ЗНП → основание | ТЧ `Продукция.Заказ` | шаг 1 запроса |
| Связь этапа с ЗНП | `ЭтапПроизводства2_5.ЗаказНаПроизводство` | шаг 3 запроса |
| План этапа | `ЭтапПроизводства2_5.ДатаНачала` / `ДатаЗавершения` | шаг 3 запроса |
| Факт этапа («Начат»/«Завершен») | `ЭтапПроизводства2_5.ДатаНачалаФакт` / `ДатаЗавершенияФакт` | шаг 3 запроса |
| Статусы | `Перечисление.СтатусыЗаказовНаПроизводство2_5`: `Формируется`, `КПроизводству` | отборы диаграмм и таблиц в схеме СКД |

Логика расчёта от этих имён не зависит — правки точечные, в одном-двух местах запроса.

## Расхождения с образцом, требующие подтверждения

1. **Строка 17 образца.** «Начать не ранее» 09.06, срок 30 дней, желаемая дата выпуска
   09.07 — а полоса нарисована до 17.07 (39 дней). Считаю это неточностью ручной
   разметки примера и строю полосу ровно на срок (до 09.07). Если полоса должна
   учитывать выходные/график работы — это отдельное правило, его в ТЗ нет.
2. **Этап без факта.** В образце такие этапы просто без полосы. Согласовано ранее
   правило «факт где есть, иначе план этапа» — реализовано именно так; полоса
   плановыми датами. Если нужно как в образце (не рисовать вовсе) — правится
   одним условием в шаге 3.
3. **Несколько оснований у одного ЗНП.** Заказ попадёт в диаграмму под каждым
   основанием, срок берётся из своего основания. В образце такого случая нет.
4. **Заказы без основания или без «Срока изготовления»** строятся по «Желаемой дате
   выпуска». Возможен вариант — не показывать их или выделять отдельно.

## Открытые вопросы

1. Нужны ли отборы по подразделению / менеджеру / номенклатуре?
2. Нужно ли показывать заказы в статусе «Закрыт» (сейчас нет)?
3. Требуется ли цветовое кодирование как в образце (план — жёлтый, факт — красный)?
   В диаграмме Ганта СКД цвета серий задаются палитрой; при необходимости
   фиксируем цвета серий «План»/«Факт» вручную.
