# 02. Чек-лист тестирования базы `erp_copy2`

Базис — типовая **1С:ERP УП 2, ред. 2.5**. Каждый раздел построен одинаково:
**объекты → ключевые связи → проверки**. Связи выписаны отдельно, потому что
основная масса дефектов в ERP живёт не внутри объекта, а на стыке объектов.

**Легенда**

- **Тип:** `А` — автоматизируется в Vanessa, `Р` — ручной, `А/Р` — частично
  (автотест проверяет основной путь, руками добивается вариативность).
- **Прио:** `P0` — блокирует релиз, `P1` — важно, `P2` — желательно.

**Как адаптировать:** сверьте с `db_statistics.csv` (см. [01](01-collect-db-structure.md))
и вычеркните разделы с нулевой заполненностью.

## ЦЕЛ — целостность данных и НСИ

Фундамент. Если НСИ противоречива, все остальные тесты будут падать по
ложным причинам — этот блок гоняется первым.

### Объекты

`Организации`, `Партнеры`, `Контрагенты`, `ДоговорыКонтрагентов`,
`СоглашенияСКлиентами` / `СоглашенияСПоставщиками`, `Номенклатура`,
`ВидыНоменклатуры`, `ХарактеристикиНоменклатуры`, `СерииНоменклатуры`,
`УпаковкиНоменклатуры`, `Склады` (`СтруктураПредприятия`), `Подразделения`,
`ФизическиеЛица`, `БанковскиеСчета`, `Кассы`, `СтатьиДоходов`, `СтатьиРасходов`,
`СтатьиДвиженияДенежныхСредств`, `ГруппыФинансовогоУчетаНоменклатуры`,
`НалоговыеГруппыНоменклатуры`, `ВидыЦен`, `ЦеновыеГруппы`.

### Ключевые связи

```
Партнёр ──1:N──> Контрагент ──1:N──> Договор
   │                                    │
   └──1:N──> Соглашение с клиентом <────┘
Номенклатура ──N:1──> ВидНоменклатуры ──> {использовать характеристики? серии? упаковки?}
Номенклатура ──N:1──> ГруппаФинансовогоУчёта ──> счета учёта в рег. учёте
Организация ──1:N──> БанковскийСчёт, Касса, Склад, Подразделение
Склад ──N:1──> СтруктураПредприятия ──> {ордерная схема? адресное хранение?}
```
