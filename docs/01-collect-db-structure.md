# 01. Сбор фактической структуры базы `erp_copy2`

Цель этапа — получить машиночитаемый срез того, что **реально заведено** в базе,
чтобы чек-лист описывал вашу конфигурацию, а не абстрактную типовую.

Нужны три артефакта:

| Артефакт | Что даёт | Чем снимается |
|---|---|---|
| `db_statistics.csv` | какие объекты заполнены и насколько | `tools/DbStatistics.bsl` |
| `object_links.csv` | граф связей между объектами | `tools/ObjectLinksMap.bsl` |
| `integrity_report.csv` | битые ссылки, дубли, циклы | `tools/IntegrityChecks.bsl` |
| `config_xml/` *(опционально)* | полная структура метаданных + доработки | `tools/dump-config.cmd` |

---

## 1. Заполненность объектов → `db_statistics.csv`

Отвечает на вопрос «какие объекты в базе живые». Это основной инструмент
отсечения лишних проверок: если в `Документ.ЗаказНаПроизводство` ноль записей —
производственный блок из чек-листа выкидывается целиком.

**Как запустить.** Код из `tools/DbStatistics.bsl` — тело обработки. Варианты:

- вставить в внешнюю обработку с формой и кнопкой;
- или выполнить через «Консоль запросов/кода» (ИТС, `КонсольКода.epf`);
- или через `Сервис → Дополнительные обработки` в режиме предприятия.

> ⚠️ Запускать под пользователем с полными правами, иначе часть таблиц
> вернёт `-1` (нет доступа) и картина будет неполной.

**Что на выходе** — CSV вида:

```csv
Вид;ПолноеИмя;Синоним;Количество;ПометкаУдаления
Справочник;Справочник.Номенклатура;Номенклатура;18432;127
Справочник;Справочник.Партнеры;Партнёры;2914;33
Документ;Документ.ЗаказКлиента;Заказ клиента;51203;418
Документ;Документ.ЗаказНаПроизводство;Заказ на производство;0;0
РегистрНакопления;РегистрНакопления.ТоварыНаСкладах;Товары на складах;1204551;
```

**Как читать:**

- `Количество = 0` → объект не используется, проверки по нему исключить;
- `Количество > 0`, но объекта нет в чек-листе → это доработка либо
  неучтённая подсистема, проверки надо дописать;
- аномально высокая доля `ПометкаУдаления` → кандидат на проверку
  «удаление помеченных объектов» и на разбор бизнес-процесса.

## 2. Карта связей → `object_links.csv`

Отвечает на вопрос «как объекты связаны». Именно из неё выводятся проверки
целостности и сценарии сквозных тестов.

Скрипт `tools/ObjectLinksMap.bsl` обходит метаданные и для каждого ссылочного
реквизита (в шапке, в табличных частях, в измерениях/ресурсах регистров)
пишет ребро графа:

```csv
Источник;Путь;Реквизит;Приёмник;Обязательный;ТипСоставной
Документ.ЗаказКлиента;Шапка;Партнер;Справочник.Партнеры;Да;Нет
Документ.ЗаказКлиента;Шапка;Контрагент;Справочник.Контрагенты;Да;Нет
Документ.ЗаказКлиента;Шапка;Соглашение;Справочник.СоглашенияСКлиентами;Нет;Нет
Документ.ЗаказКлиента;ТЧ.Товары;Номенклатура;Справочник.Номенклатура;Да;Нет
Документ.ЗаказКлиента;ТЧ.Товары;Характеристика;Справочник.ХарактеристикиНоменклатуры;Нет;Нет
РегистрНакопления.ТоварыНаСкладах;Измерение;Склад;Справочник.Склады;Да;Нет
```

**Как использовать:**

1. **Обязательные связи** (`Обязательный = Да`) → проверки «документ не
   проводится с незаполненным реквизитом» (негативные тесты).
2. **Составные типы** (`ТипСоставной = Да`) → каждый тип надо покрыть отдельно,
   это классический источник необнаруженных ошибок.
3. **Входящие рёбра** для справочника → сценарии «нельзя пометить на удаление
   объект, используемый в документах».
4. **Цепочки** (Заказ → Реализация → Счёт-фактура) → сквозные E2E-сценарии
   для Vanessa.

## 3. Проверки целостности → `integrity_report.csv`

`tools/IntegrityChecks.bsl` ищет то, что ломает тесты ещё до их написания:

- битые ссылки (ссылка на несуществующий объект);
- дубли по ключевым реквизитам (ИНН+КПП контрагентов, артикул номенклатуры,
  код/наименование справочников);
- зацикленные иерархии (родитель ссылается сам на себя через цепочку);
- незаполненные обязательные реквизиты в проведённых документах;
- документы с движениями, но без проведения (и наоборот).

Штатная альтернатива/дополнение — **«Тестирование и исправление»** в
конфигураторе и обработка **`ПоискИУдалениеДублей`** из БСП. Их результат тоже
приложите.

## 4. Выгрузка конфигурации в XML *(опционально, но очень полезно)*

Даёт полную картину метаданных, включая доработки, расширения, роли и RLS.

```cmd
"C:\Program Files\1cv8\8.3.24.1548\bin\1cv8.exe" DESIGNER ^
  /S "erpdevs\erp_copy2" ^
  /N "Администратор" /P "***" ^
  /DumpConfigToFiles "D:\dump\erp_copy2_xml" -Format Hierarchical ^
  /Out "D:\dump\dump.log" /DisableStartupMessages
```

Отдельно — список расширений и их состав:

```cmd
"...\1cv8.exe" DESIGNER /S "erpdevs\erp_copy2" /N "Администратор" /P "***" ^
  /DumpCfg "D:\dump\ext.cfe" -Extension "ИмяРасширения"
```

> Выгрузка целиком тяжёлая (ERP — десятки тысяч файлов). Если полная не нужна,
> достаточно `db_statistics.csv` + `object_links.csv` + список расширений.

## 5. Что ещё приложить

Мелочи, которые сильно влияют на чек-лист:

- **Включённые функциональные опции.** Запрос по
  `РегистрСведений.ЗначенияФункциональныхОпций` или скрин раздела
  *НСИ и администрирование*. Определяет, какие блоки ERP вообще активны
  (ордерная схема, серии, характеристики, давальческое сырьё, ВЭД, ЗУП в составе).
- **Список организаций** и их системы налогообложения (ОСН/УСН, НДС, обособки).
- **Профили групп доступа** и роли — для блока проверок прав и RLS.
- **Планы обмена и узлы** — какие интеграции живые (БП, ЗУП, Розница, EDI, сайт).
- **Версия платформы и релиз конфигурации** (`Справка → О программе`).
- **Список доработок**, если ведётся (задачи/описания изменений).

## Быстрый минимум

Если времени мало — хватит двух шагов, они дают наибольший эффект:

```
1) DbStatistics.bsl        → db_statistics.csv
2) скрин функциональных опций / список активных разделов
```

Этого достаточно, чтобы срезать неиспользуемое и расставить приоритеты.
