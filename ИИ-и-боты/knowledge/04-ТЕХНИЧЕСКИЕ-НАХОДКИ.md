# Технические находки: API, CORS, подводные камни

Всё проверено вживую в августе 2026. Эндпоинты неофициальные — те же, что
использует сайт tradingview.com, — и могут измениться без предупреждения.

---

## 1. Скринер TradingView

```
POST https://scanner.tradingview.com/crypto/scan     # крипта
POST https://scanner.tradingview.com/global/scan     # смешанные тикеры
POST https://scanner.tradingview.com/america/scan    # акции США
```

Тело запроса — либо список тикеров, либо фильтр по рынку:

```json
{
  "symbols": {"tickers": ["MEXC:BTCUSDT"], "query": {"types": []}},
  "columns": ["name", "close", "RSI|60", "ATR|60"]
}
```

```json
{
  "filter": [{"left": "exchange", "operation": "equal", "right": "MEXC"},
             {"left": "name", "operation": "match", "right": "USDT$"}],
  "columns": ["name", "close", "volume"],
  "sort": {"sortBy": "volume", "sortOrder": "desc"},
  "range": [0, 2000]
}
```

Ответ: `{"totalCount": N, "data": [{"s": "MEXC:BTCUSDT", "d": [значения по колонкам]}]}`.

### Суффиксы таймфреймов

Приписываются к имени колонки: `|1` `|5` `|15` `|30` `|60` `|120` `|240` `|1W` `|1M`.
Без суффикса — дневной таймфрейм. Пример: `RSI|240` — RSI на 4 часах.

### Полезные колонки

`close` `change` `volume` `ATR` `RSI` `CCI20` `MACD.macd` `MACD.signal`
`Recommend.All` `Recommend.MA` `Recommend.Other` `Stoch.K` `Stoch.D` `ADX` `AO`
`Mom` `W.R` `UO` `BBPower` `BB.upper` `BB.lower` `KltChnl.upper` `KltChnl.lower`
`EMA10…EMA200` `SMA10…SMA200` `market_cap_basic` `price_earnings_ttm`
`Perf.W` `Perf.1M` `Perf.YTD` `sector` `exchange`.

Рейтинги `Recommend.*` лежат в диапазоне [−1, 1]; пороги TradingView:
≥0,5 STRONG_BUY · ≥0,1 BUY · >−0,1 NEUTRAL · >−0,5 SELL · иначе STRONG_SELL.

## 2. Три находки, без которых сканер бы не работал

### 2.1. Content-Type обязан быть text/plain

TradingView отдаёт CORS, отражая любой Origin (включая `null`, то есть файл,
открытый с диска). Но в `access-control-allow-headers` у них только
**`Referer, Accept`** — заголовка `content-type` там нет.

Значит `Content-Type: application/json` вызовет предзапрос CORS, и браузер
его завернёт. А `text/plain` входит в белый список CORS и предзапрос **не вызывает**.
Сервер при этом прекрасно разбирает тело как JSON.

```js
fetch("https://scanner.tradingview.com/crypto/scan", {
  method: "POST",
  headers: {"Content-Type": "text/plain;charset=UTF-8"},   // не application/json!
  body: JSON.stringify(body),
});
```

### 2.2. MEXC напрямую из браузера недоступен

`api.mexc.com` в ответе **не отдаёт** `access-control-allow-origin` — только
`access-control-expose-headers: x-cache`. Любой браузер заблокирует чтение ответа.

Из серверного кода (curl, Node) MEXC работает прекрасно:

```
GET https://api.mexc.com/api/v3/klines?symbol=BTCUSDT&interval=60m&startTime=...&endTime=...&limit=1000
```

Интервалы: `1m 5m 15m 30m 60m 4h 1d 1W 1M`. История — примерно 500 дневных
свечей назад. Параметры `startTime` и `endTime` работают только **вместе**:
если передать один `startTime`, он игнорируется и возвращаются последние свечи.

Фьючерсный API MEXC (`contract.mexc.com`) закрыт их CDN — отдаёт 403.
Спотовые цены практически совпадают с бессрочными контрактами, для расчётов хватает.

**Итог:** в браузере данные MEXC берём через TradingView (там ~1700 пар MEXC
к USDT и 3178 пар всего), в серверных скриптах — напрямую с api.mexc.com.

### 2.3. Скринер сортирует по объёму в монетах

`volume` для крипты — это объём в **базовой валюте**, а не в долларах.
Из-за этого топ по `volume` занимают микро-токены с триллионами единиц
(AIDOGE по 1e-11), а BTC и ETH проваливаются далеко вниз.

Готовой колонки оборота в долларах нет — проверены `Value.Traded`,
`24h_vol_cmc`, `total_value_traded`, `24h_vol`: все возвращают `None`.

**Решение:** запрашивать все пары (`range: [0, 2000]` → 1682 пары, ~1 МБ, 1,1 с),
считать `volume × close` на своей стороне и по нему брать топ-N.

## 3. Поиск тикеров

```
GET https://symbol-search.tradingview.com/symbol_search/v3/?text=apple&hl=0&lang=en&domain=production
```

Возвращает совпадения с биржей, типом, ISIN/CUSIP. Работает и по ISIN.
В названиях приходят теги `<em>` для подсветки — их надо вычищать.

## 4. Чего сделать нельзя

**Артефакт не может ходить в сеть.** Строгая политика безопасности блокирует
любые внешние запросы (кроме Google Fonts). Живой сканер внутри артефакта
невозможен в принципе — только статический снимок данных.

**Код чужих скриптов TradingView не выгрузить.** Страницы
`tradingview.com/script/...` содержат описание, но сам Pine подгружается через
`pine-facade.tradingview.com`, требующий авторизации.

**Автообновление артефакта из фоновой сессии ненадёжно.** Классификатор
разрешений блокирует публикацию и постановку таймеров в автономном пробуждении.

## 5. Подводные камни Pine Script v6

* **Нельзя** перечислять присваивания через запятую: `a := 1, b := 2` —
  ошибка. Только по строке на присваивание. То же для `var`-объявлений.
* Функции объявляются **только на верхнем уровне**; внутри `if` нельзя.
* `qty_percent` в `strategy.exit` считается от **текущей** позиции, а не от
  исходной. Лесенка 20/20/20/20/20 «съезжает»: второй выход возьмёт 20% от
  оставшихся 80%. Надо пересчитывать долю через отношение текущей позиции
  к исходной.
* Уже сработавшую цель **нельзя переоткрывать** — повторный вызов
  `strategy.exit` с тем же id создаст новый ордер. Нужны защёлки по достигнутым целям.
* В опубликованном коде Squeeze Momentum от LazyBear есть опечатка:
  в расчёте BB стоит `multKC` вместо `mult`. Автор исправил в обновлении.

## 6. Конвейер распознавания видео

Для перевода записей экрана в структурированные данные:

```bash
# ffmpeg через pip, если apt недоступен
pip install imageio-ffmpeg
FF=$(python3 -c "import imageio_ffmpeg;print(imageio_ffmpeg.get_ffmpeg_exe())")

# кадры: 3 к/с, отбрасывание дубликатов, обрезка шапки и навигации
$FF -i video.mp4 -vf "fps=3,mpdecimate=hi=64*24:lo=64*12:frac=0.15,scale=810:-1,crop=810:1180:0:400" \
    -vsync vfr -q:v 2 frames/u_%03d.jpg

# склейка по три кадра в тайл — втрое меньше чтений изображений
$FF -i a.jpg -i b.jpg -i c.jpg -filter_complex "hstack=inputs=3" -q:v 2 tile.jpg
```

Шаг между кадрами 4 при склейке по 3 даёт достаточное перекрытие, чтобы ничего
не пропустить при плавной прокрутке.

**Дедупликация** сигналов — по ключу `(время закрытия, тип, пара, цена входа)`.
Цена входа в ключе обязательна: у Golden бывает несколько разных сигналов на одну
пару в одну минуту.
