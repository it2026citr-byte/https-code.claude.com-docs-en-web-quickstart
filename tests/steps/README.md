# Собственная библиотека шагов `ШагиТестированияERP.epf`

Здесь должна лежать внешняя обработка с шагами, которых нет в штатной поставке
Vanessa Automation. Это фундамент всех сценариев: без проверки движений
UI-тест доказывает лишь то, что кнопка нажалась.

Обработка создаётся штатным способом: в VA есть шаблон библиотеки шагов
(«Создать библиотеку шагов»), в него добавляются экспортные процедуры
с аннотациями шагов.

## Шаги, используемые в примерах `.feature`

### Подготовка данных (фикстуры)

| Шаг | Что делает |
|---|---|
| `Дано в базе есть склад "%1" без ордерной схемы` | находит или создаёт склад с нужными настройками |
| `Дано в базе есть склад "%1" с ордерной схемой на отгрузку` | то же, с ордерной схемой |
| `Дано в базе есть номенклатура "%1" с остатком %2 на складе "%3"` | создаёт номенклатуру и приходует нужное количество |
| `Дано в базе есть клиент "%1" с типовым соглашением "%2"` | создаёт партнёра, контрагента, договор, соглашение |
| `Дано в базе есть клиент "%1" с кредитным лимитом %2` | то же + лимит в соглашении |
| `Дано у клиента "%1" задолженность %2` | доводит взаиморасчёты до нужного состояния |
| `Дано у клиента "%1" есть просроченная задолженность` | создаёт отгрузку с истёкшим сроком оплаты |
| `Дано регламентные задания отключены` | снимает расписания на время прогона |
| `Дано установлена дата запрета изменения "%1"` | настраивает даты запрета |

> Фикстуры должны быть **идемпотентными**: повторный вызов не создаёт дубль,
> а находит существующий объект. Иначе база распухнет за неделю прогонов.

### Работа со ссылками

| Шаг | Что делает |
|---|---|
| `И я запомнил ссылку на текущий документ как "%1"` | сохраняет ссылку в контекст сценария |
| `Дано я открыл документ по ссылке "%1"` | открывает форму ранее запомненного документа |

### Проверка движений и остатков — ядро библиотеки

| Шаг | Что делает |
|---|---|
| `Тогда движения документа "%1" по регистру "%2" содержат строку:` | сверяет движения с таблицей Gherkin |
| `Тогда движения документа "%1" по регистру "%2" не пустые` | проверяет факт наличия движений |
| `Тогда движения документа "%1" по всем регистрам пустые` | для проверки распроведения |
| `Тогда остаток по регистру "%1" склад "%2" номенклатура "%3" равен %4` | запрос остатка |
| `Тогда отрицательных остатков по регистру "%1" нет` | интегральная проверка |
| `Тогда отрицательных остатков по счёту "%1" на "%2" нет` | то же для бухгалтерских счетов |
| `Тогда сумма проводок Дт "%1" Кт "%2" за период равна %3` | проверка проводок |

### Ускоренное создание документов

Шаги-обёртки, которые сокращают сценарии и уменьшают их хрупкость
(вместо десяти UI-шагов — один):

| Шаг |
|---|
| `Когда я создаю документ "%1" для клиента "%2"` |
| `И в таблице "Товары" я добавляю номенклатуру "%1" в количестве %2` |
| `И в таблице "Товары" я добавляю номенклатуру "%1" в количестве %2 по цене %3` |
| `Тогда документ проведён` |
| `Тогда документ не проведён` |
| `И я закрываю текущее окно без сохранения` |

### Отчёты и закрытие месяца

| Шаг |
|---|
| `Когда я формирую отчёт "%1" за период "%2"-"%3"` |
| `Тогда все этапы закрытия месяца выполнены успешно` |
| `Тогда в результатах закрытия месяца нет ошибок` |
| `Дано я запомнил итоги по счетам за период "%1"-"%2" как "%3"` |
| `Тогда итоги по счетам за период "%1"-"%2" совпадают с "%3"` |

## Порядок реализации

1. Сначала — проверки движений и остатков. Они окупаются немедленно и
   переиспользуются во всех сценариях.
2. Затем — фикстуры подготовки данных.
3. В последнюю очередь — обёртки создания документов.

Ориентировочно неделя работы, после чего написание одного сценария
занимает часы, а не дни.
