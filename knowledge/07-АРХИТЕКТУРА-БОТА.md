# Источник сигналов: архитектура

Согласовано 22 августа 2026. Форма — Telegram-бот с ядром на компьютере
пользователя. Ниже — принятые решения и обоснования.

## Почему бот, а не чат и не сайт

**Чат (Claude) не может быть источником.** Между сообщениями сессии не
существует, контейнер выключается после простоя. Автопробуждения проверены и
блокируются классификатором разрешений (см. `04-ТЕХНИЧЕСКИЕ-НАХОДКИ.md`, п. 4).

**Сайт/артефакт не может мониторить.** Страница работает, только пока открыта.
Для функции «сообщить, что пора выходить» это дисквалифицирующе.

**Telegram-бот** даёт push на телефон без открытого приложения и двусторонний
диалог. Сканер-сайт остаётся витриной «посмотреть глазами».

## Каркас

```
ЯДРО (компьютер пользователя, Node.js)
├─ Планировщик — просыпается на закрытии свечи
├─ Загрузчик данных
│    TradingView screener → широкий скан ~1700 пар MEXC
│    MEXC klines        → точные свечи по кандидатам
├─ Реестр стратегий      ← сюда добавляются новые
├─ Монитор позиций       цели / стоп / нарушение стратегии
├─ Советник (Anthropic API) — второе мнение, не в критическом пути
├─ Исполнитель — заглушка (позже: ключи MEXC)
└─ SQLite: signals, positions, users, candles, settings
        │ Telegram Bot API
     телефон
```

## Контракт стратегии

Каждая стратегия — один файл, отвечающий и за вход, и за смерть позиции.
Та стратегия, что открыла сделку, лучше всех знает, когда её посылка умерла.

```js
export default {
  id: "golden-reverse",
  timeframe: "1h",
  evaluate(c)            // → { side, entry, sl, targets[] } | null
  invalidated(c, pos)    // → { reason, text, level } | null
}
```

Проверки нарушения (выбраны пользователем; таймаута сознательно нет):

| Проверка | Как считаем |
|---|---|
| Встречный сигнал | `evaluate()` этой же стратегии выдал противоположную сторону |
| Слом структуры (CHoCH) | Детектор ног из SMC, перенос из `universal-strategy.pine` |
| Разворот momentum | Гистограмма Squeeze Momentum против позиции ≥2 бара подряд |

## Два режима работы

Переключение — командой `/фокус` и `/скан`, состояние живёт в SQLite и
переживает перезапуск.

| | Обычный (скан) | **Фокус** |
|---|---|---|
| Поиск новых монет | да, ~1700 пар раз в 15 мин | **выключен полностью** |
| Проверка позиций | на закрытии свечи 15м | **каждые 10 секунд** |
| Таймфрейм проверки | родной ТФ стратегии | 1м + 5м + родной |
| Задержка реакции | до 15 минут | до 10 секунд |
| Трафик | ~1 МБ на цикл | ~20 КБ на пару |
| Непринятые сигналы | отслеживаются | заморожены |

Смысл фокуса: ресурсы целиком на взятые сделки. Трафик падает на два порядка,
поэтому опрашивать можно почти непрерывно.

### Двухуровневые тревоги — то, ради чего нужен фокус

В обычном режиме CHoCH подтверждается только на закрытии часовой свечи —
до часа опоздания. В фокусе структура считается **внутри бара**:

* 🟡 **предварительно** — структурный лоу уже пробит, ждём закрытия свечи;
* 🔴 **подтверждено** — свеча закрылась, выходи до стопа.

Жёлтый даёт фору в десятки минут. Это и есть выигрыш от режима.

### Авто-переключение

При нуле открытых позиций фокус сам возвращается в скан с уведомлением.
Отключается настройкой.

## Нитка по сделке

Карточка сигнала — якорь. Её id хранится в `positions.msg_id`, и каждое
последующее событие по позиции уходит ответом на неё: взятие, достижение
цели, перенос стопа в безубыток, слом стратегии, закрытие. В чате
складывается нитка по каждой сделке вместо перемешанной ленты.

Если карточку удалили, событие отправляется обычным сообщением —
`allow_sending_without_reply`, потеря сообщения недопустима.

## Журнал и месячная история

Бот ведёт append-only ленту событий в таблице `journal` и выгружает её
помесячно в два файла:

* `storage/journal/ГГГГ-ММ.csv` — таблица сделок. **Первые семь колонок
  совпадают с `golden-signals-all.csv`** (Closed, Type, Pair, Status,
  Target_Reached, Entry_price, Stop_Loss), дальше добавлены Strategy,
  Opened, R, Timeframe. Значит наши сделки и база Golden анализируются
  одним скриптом;
* `storage/journal/ГГГГ-ММ.log.txt` — построчная лента всего: выдача
  сигнала, взятие в работу, каждая цель, стоп, слом стратегии.

Статусы записываются в терминах Golden (`Target 3`, `Stop Loss hit`,
`Cancelled`) плюс собственный `Strategy broken` — его у Golden нет,
потому что у них нет выхода по слому структуры.

Отчёты уходят в чат сами:

| Когда | Что |
|---|---|
| Ежедневно в `reportHourUtc` | карточки закрытых за день, как в приложении, плюс строка итога |
| Первого числа | итог месяца по статусам и по стратегиям, оба файла вложением |

Срок проверяется раз в минуту сверкой с журналом, а не таймером в памяти —
поэтому отчёт, пропущенный из-за выключенного компьютера, уходит при запуске.

Пустая дневная сводка не отправляется: если закрывать было нечего, бот молчит.

## Связь с Claude — отложено

Бот обращается к модели через **Anthropic Messages API** (ключ с
console.anthropic.com). В системный промпт упаковывается содержимое
`knowledge/` — разбор Golden, технические находки, описания стратегий —
и кэшируется, поэтому повторные вызовы дешёвые.

Честное ограничение: это **не этот чат**. Истории разговора у советника нет,
есть база знаний. И он **не в критическом пути**: может подтвердить,
прокомментировать, возразить — но не открывает и не закрывает позиции.
Решение всегда за детерминированными правилами стратегии.

Когда бот зовёт советника:

1. Кнопка «🧠 Спросить Claude» под любой позицией — ручной разбор.
2. **Конфликт проверок** — одна сработала, две молчат. Вместо слепого алерта
   арбитраж по свечам.
3. Цена подошла к стопу вплотную, но ни одна проверка не сработала —
   «досиживать или выходить».
4. Вечерний разбор закрытых за день сделок, предложения по стратегиям.
5. `/спроси <текст>` — свободный вопрос с текущим снимком рынка.

Лимит вызовов в час настраивается, чтобы не жечь бюджет.

## Данные для фьючерсов

Фьючерсный API MEXC (`contract.mexc.com`) отдаёт 403. Поэтому широкий скан и
котировки перпетуалов — TradingView по тикерам `MEXC:INJUSDT.P`, точные свечи
для индикаторов — спот `api.mexc.com` (расхождение в десятых процента,
для ATR и структуры несущественно). Из Node CORS нет.

## Компьютер не работает круглосуточно

Принятый риск. Смягчение:

* всё состояние в SQLite на диске — выключение не теряет позиций;
* **догоняющий скан при старте**: свечи за пропущенный период прогоняются
  через монитор, и если позицию надо было закрыть — бот говорит прямо,
  когда именно сломалось и где цена сейчас;
* в каждом сообщении — когда бот последний раз видел рынок.

Переезд на VPS = копирование папки и `npm start`, код не меняется.

## Стратегии на старте

1. **Golden-Reverse** — цели 0,5/1/1,5/2/2,5 R, стоп ≈1,5×ATR(1ч) либо за
   свингом, риск **1%** на сделку (не 30%, как у оригинала).
2. **Консенсус UT Bot + CCI + Squeeze** — из `universal-strategy.pine`.

Новая стратегия = новый файл в `strategies/`, ядро подхватывает само.
`/стата` показывает R-статистику по каждой отдельно.

## Автоторговля

Интерфейс исполнителя определяется сразу (`open`, `close`), реализация —
заглушка в лог. Ключей API биржи на машине на этом этапе нет.

## Этапы

| | Что | Результат |
|---|---|---|
| 1 | Каркас: SQLite, планировщик, загрузчик, бот | Бот отвечает, пишет цену BTC |
| 2 | Реестр + Golden-Reverse + кнопки «Взял/Пропустил» | Живые сигналы на телефон |
| 3 | Монитор: цели, стоп, три проверки нарушения | Алерты на выход |
| 4 | **Режим фокуса + двухуровневые тревоги** | Реакция за 10 секунд |
| 5 | Вторая стратегия | Сравнение стратегий по R |
| 6 | Бэктест на исторических свечах | Проверка до реальных денег |
| — | Советник на Anthropic API | **Отложен.** Единственная платная часть |

## Что нужно от пользователя

* Токен бота: `@BotFather` → `/newbot`.
* Ключ Anthropic API — **не сейчас.** Советник отложен; всё остальное

  с оплатой по токенам, порядка 4–8 $ в месяц при десятке разборов в день.
